- 날짜: 2026-09-19
- 작성자: CC 세션 B (PR #3), 정리·결정 김요섭

## 가설

스펙 v0.2.0 의 3장·6장·9장과 v0-plan 5~7장을 코드로 옮기면 구현자마다 다르게 읽을 수 있는 지점이 드러날 것이다. 그 지점을 구현으로 메우지 않고 모아 판정하면, 같은 알고리즘이 구현마다 다른 상태 비율을 내는 일을 v0 첫 실측 전에 막을 수 있다.

## 실험

`core/focus-core` 에 기록 스키마, StateFinalizer, 로그 재생, GT 대조 도구를 구현하고(PR #3), 합성 로그와 단위 테스트로 규칙마다 경계 조건(N / N+1 버킷, 소급 범위, lifecycle gap 2분·10분·11분, 반응 구간)을 돌렸다. 구현 중 스펙이 정하지 않았거나 서로 어긋나는 지점 15건과, 6장 스키마와 v0 부분집합에 없어서 v0 합격선을 잴 수 없는 필드 12종을 PR #3 본문에 보고했다.

## 관찰

9. flapping "10분당 1회" 의 분모와 상태 비율 오차의 분모(3장은 INVALID·일시정지 제외, 7장은 "각 상태") 불일치.
10. lifecycle gap 의 PHONE/PAUSED 판정 주체가 "판정에 따라" 뿐(9장); Android 에서 어떤 경우가 gap 인지 없음.
11. 10분 초과 종료 시 interval 을 남기는지, "초과" 가 엄격한지 없음(9장).
12. 프레임 검출을 초 단위 참/거짓으로 바꾸는 비율 임계값이 없음(3장, 6장).
13. T7c "camera_occluded 0초" 와 T5b "재거치 확정 0회" 는 final_state 만으로 잴 수 없음(무효 사유·재거치 사건 필드 없음).
14. T4b 복귀 뒤 자동 재개(얼굴 3초)가 큐 뒤 3초 반응 구간과 정확히 겹쳐 PAUSED 초가 채점에 들어갈 수 있음; "5초 안에 재개" 와 맞지 않음.
15. v0-plan 4장 실행 순서가 H(GT 도구)를 G(골격) 앞에 두지만 H 는 G 의 소급 정의를 입력으로 함.

## 결정

CHANGELOG v0.2.1 (2026-09-19) 로 기록. 코드·테스트·README 는 PR #3 에 반영. `spec_version` 은 "0.2.0" 유지, `feature_schema_version` 은 "0.2.1". 새 수치는 전부 `ParameterSet` 에 두고 "초기값" 으로 표시.

A. 모호·충돌 15건 판정

1. `t_mono_ms` 는 1초 버킷 `[t, t+1000)` 의 시작. 버킷은 세션 시작 시각에 정렬하고 레코드는 버킷이 끝날 때 기록한다. (현재 코드 확정)
2. "N초 연속" = 조건을 만족한 버킷 N개 연속. 소급이 있는 상태(ABSENT, PRONE, PHONE)는 N번째 레코드에서 확정, 후보 시작 = 첫 버킷의 시작. 소급이 없는 상태(AWAY, PAUSED)는 처음 N개 버킷은 기존 분류를 유지하고 N+1번째 버킷부터 그 상태: AWAY 는 밖 4버킷 뒤 5번째부터, 장기 이탈은 16번째부터, PAUSED 는 120버킷 뒤 121번째부터.
3. 소급이 덮어쓰는 범위: ABSENT·PRONE 소급은 raw_state 가 PRESENT, AWAY, INVALID(face_missing_unconfirmed, head_missing, face_unstable)인 초만. PHONE 소급은 위에 더해 INVALID(phone_shake). 어떤 소급도 PHONE, PAUSED, 환경 INVALID(low_light, camera_occluded, fps_low, quality_proxy, redock_pending, recalibration)는 덮지 않는다. 환경 INVALID 버킷은 카메라 기반 후보(ABSENT, PRONE, AWAY 유예, 머리 미검출 저움직임 카운터)를 리셋하고 IMU 기반 집어 듦 후보는 리셋하지 않는다.
4. 상태는 7개(PAUSED 포함). 우선순위 PHONE > PAUSED > INVALID(환경) > ABSENT > PRONE > AWAY > PRESENT. 자동 일시정지 중에도 초당 레코드는 계속 남기고 상태는 PAUSED(소급 없음). 레코드를 남길 수 없는 lifecycle gap 만 interval 로 남긴다. "세션 시간에서 뺀다"는 집계 규칙: PAUSED 와 INVALID 는 비율의 분모에서 빼고 초 수를 따로 보고한다. v0-plan 1장의 "여섯 개" 는 오기.
5. T2 의 2초 자리 비움: 기대 상태는 INVALID. "ABSENT 0초" 같은 금지 조건은 반응 3초를 포함한 행동 구간 전체에서 센다. (현재 코드 확정)
6. 폰 재거치: 거치 자세에서 벗어난 채 정지(RESTING_OFF_DOCK)하면 집어 듦 확정 여부와 무관하게 재거치 대기 — 그 첫 버킷부터 60초까지 INVALID(redock_pending), 이후 PHONE(소급 없음); 다시 움직이면 7번 규칙으로 돌아가고 타이머는 다음 정지에서 새로 센다. 재거치 확정: 거치 자세 ±10° 안에서 redock_stationary_confirm_ms(2000) 연속 정지, 또는 탭; 확정 뒤 recalibration_ms(20000) 동안 INVALID(recalibration). GT: phone_use_on_flat_surface 구간 시작 = 정지 시작. phone_redock_recalibrating 구간 길이가 2000 + 20000ms 보다 짧으면 GT 파서가 경고한다.
7. 집어 듦: imu_state 가 LIFTED 또는 MOVING 인 버킷이 3개 연속이면 확정(기울기 분기와 분산 분기 모두 3초). 3개 미만이면 그 버킷들은 INVALID(phone_shake).
8. 검출 지연: interval 시작 큐부터, raw_state 가 그 interval 의 최종 기대 상태로 처음 바뀐 레코드의 t 까지. 1초 양자화가 있음을 README 에 적는다. (현재 코드 확정)
9. flapping 의 분모는 기대 상태가 일정한 구간의 채점 초 합(현재 코드 확정). 상태 비율 오차는 기대·측정 각각 INVALID 와 PAUSED 를 분모에서 뺀 비율로 계산한다. INVALID 비중의 차이는 별도 줄로 보고한다.
10. lifecycle gap 의 사유는 기기 층이 GapReason 으로 넘긴다(현재 코드 확정). Android 는 화면이 꺼지거나 다른 앱을 써도 측정이 계속되므로 APP_SWITCH·SCREEN_LOCK gap 을 내지 않는다(초당 레코드의 PHONE 으로 남는다). GapReason.PROCESS_DEATH 추가: interval 을 만들지 않고 마지막 기록 시각으로 세션을 닫는다.
11. 10분 "초과" 는 엄격 초과. 초과하면 interval 을 만들지 않고 진입 시각에 session_end(LIFECYCLE_GAP_TIMEOUT). (현재 코드 확정)
12. 얼굴 검출 비율 임계값을 둘로 나눈다. face_missing_max_ratio = 0.2: 그 미만이면 G1 의 "얼굴 미검출" 버킷. face_present_min_ratio = 0.5: 그 이상이어야 방향(G2)을 판정. 0.2 이상 0.5 미만은 INVALID(face_unstable), zone_status = no_head_pose. NaiveBaselineEngine 의 미검출 기준은 face_missing_max_ratio.
13. proxy 를 없앤다. T7c = leave_seat_plain_background 구간 전체에서 invalid_reason == camera_occluded 인 초 0. T5b = phone_use_on_flat_surface 구간 안의 redock_confirmed 사건 0회.
14. PAUSED 가 끝나는 큐 뒤의 채점 제외 구간은 6초(반응 3 + 재검출 3). 합격선은 "복귀 큐 뒤 7초 안에 재개"(resume_within_ms = 7000). v0-plan 7장의 5초는 반응 허용을 빠뜨린 오기.
15. 실행 순서 정오: A → B → G(골격) → H → C → D → E → F → G(나머지). PR #3 이 둘을 함께 넣은 것이 맞다.

B. 스키마 0.2.1 (12종 모두 수용)

- invalid_reason: low_light, camera_occluded, fps_low, quality_proxy, phone_shake, redock_pending, recalibration, face_missing_unconfirmed, head_missing, face_unstable. 상태가 INVALID 가 아니면 null.
- candidate_state, candidate_start_mono_ms (AWAY 유예도 여기에 담는다. away 전용 필드는 만들지 않는다).
- events(사건 목록): pickup_candidate, pickup_confirmed, shake, redock_confirmed{by: orientation|tap}, redock_pending_timeout, notify_reposition, auto_pause_start, auto_resume, recalibration_start, recalibration_end, zone_added{zone_id}. 각 사건에 t_mono_ms.
- screen_state {ON_UNLOCKED, ON_LOCKED, OFF} 와 app_state {FOREGROUND, BACKGROUND} 를 분리한다. PHONE(앱 기준) = ON_UNLOCKED AND BACKGROUND.
- frames_requested, frames_processed, frames_dropped, max_frame_gap_ms, gaps_over_80ms. fps_actual 은 제거한다.
- torso_match 를 제거하고 shoulder_visibility_min, torso_center_offset_ratio, torso_width_ratio 를 둔다. head_below_shoulder 를 제거하고 head_offset_below_shoulder_ratio(머리 landmark 없으면 null)를 둔다. 일치 여부와 엎드림 조건은 엔진이 ParameterSet 으로 계산한다.
- zone_status {in_zone, outside, no_head_pose}, zone_id 는 in_zone 일 때만.
- header 에 t_start_mono_ms, t_start_utc_ms. session_end 줄을 정식 형식으로: t_mono_ms, t_utc_ms, reason {USER, LIFECYCLE_GAP_TIMEOUT, PROCESS_DEATH_RECOVERED, UNKNOWN}.
- JSONL 줄 타입 calibration: calibration_id, version, t_mono_ms, zones(최대 3: zone_id, yaw·pitch 중심과 반폭), torso ROI(중심 x·y, 폭, 정규화), m0_pose, pose_jitter_floor, m0, jitter_floor, j 기준값, 거치 중력 벡터(3), 거치 가속도 분산, scene 휘도 기준, bg_tile_texture_baseline(16), bg_tile_mask(16).
- JSONL 줄 타입 timebase: camera_ts_source, camera_to_mono_offset_ns, imu_to_mono_offset_ns. 세션 시작과 1분마다.
- 데이터 경계 테스트 갱신: SecondRecord 에는 수치 배열을 허용하지 않는다(사건 목록만). calibration 줄에 한해 이름이 정해진 고정 길이 수치 목록(zones ≤ 3, 중력 벡터 3, tile 16)만 허용한다.

구현 가정(판정에 없어서 코드가 정한 것, 다음 판정 후보): 재거치 확정을 기다리는 DOCKED 정지 버킷은 INVALID(redock_pending); IMU UNKNOWN 버킷은 폰 게이트의 현재 단계를 유지(카운터를 늘리지도 끝내지도 않음); 합격선 수치(reaction 3초, resume 7000 등)는 알고리즘 파라미터가 아니라 GT 채점 규칙이라 `ParameterSet` 이 아닌 `GtRules` 에 두고 리포트의 `gt_rules` 로 남긴다.
